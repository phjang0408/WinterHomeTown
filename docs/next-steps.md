# 겨울 동네 다음 단계 (2026-11-18 맵 수정 마무리 기준)

맵 수정은 14차(2026-11-18)로 끝났다. 자세한 수정 내역은 `docs/map-changes-log.md`(프로젝트 `claude/map-changes-log.md`), 구획은 '겨울 동네 2차 구획도' 페이지를 본다.

## 남은 단계 (권장 순서)

| 순서 | 단계 | 할 일 | 끝났다고 보는 기준 |
|---|---|---|---|
| 1 | 그래픽 최적화 | 실제 기기 측정 → 거리별 단순 모델(LOD) → 그림자 정리 → 과한 소품 줄이기 → 그리기 횟수 | 데스크톱 · 맥북에서 60fps, GPU · CPU 각 10ms 안팎 |

| 4 | 환경설정 | 화질(화면 배율 · 그림자 · LOD 거리 · 나무 밀도), 소리, 조작 | 낮은 사양에서 '낮음'으로 30fps 이상 |

| 6 | 마무리 점검 | 모바일 터치, 브라우저 호환, 불러오기 시간 | 점검표 통과 |

## 1단계 그래픽 최적화 메모

- 측정: 게임에서 P 키 → '5곳 측정' → '결과 복사'. 데스크톱(Windows, Chrome)과 맥북 둘 다. 로컬 서버(`python -m http.server 8000`)로 열면 가장 깨끗하다.
- 판단: GPU ms가 높고 창을 줄이면 빨라짐 → 픽셀 문제(화면 배율 · 그림자 해상도). 창 크기와 상관없음 → 삼각형(LOD · 소품 줄이기). CPU ms가 높음 → 그리기 횟수.
- 놓인 소품 삼각형 상위(2026-11-18 13차 기준): 겨울 나무 62만(304그루) · 차 37만(세단 대당 8,712) · 벤치 35만(개당 4,194) · 소나무 24만 · 눈 더미 24만(1,164) · 도로 울타리 19만 · 점자블록 8만(개당 2,800). 전체 330만 중 그림자를 드리우는 것 256만.
- 14차 뒤 화면 삼각형(헤드리스, 그림자 포함): 시작 192만 · 공원 139만 · 단지 148만 · 강변 102만 · 역 96만.

## 1단계 그래픽 최적화 1차 (2026-11-24)

- 데스크톱 측정(RTX 4070 SUPER, Chrome, 2559×1206, 165Hz 모니터): 모든 시점이 모니터 상한(165fps) 근처. 가장 무거운 곳은 '시작'(CPU 8.0 · GPU 6.8ms, 그리기 1,348). 데스크톱은 이미 목표 안이고, 남은 기준은 맥북.
- 측정 도구 바로잡음: `renderer.info`는 그림자 패스를 세지 않았다. 성능 창이 이제 '그리기 메인 + 그림자'와 삼각형 합계를 따로 센다. '5곳 측정'은 한 바퀴 미리 돈 뒤 재고, 화질 · 배율 · 그림자 크기를 같이 적는다. 배율 · 그림자 단추로 그 자리에서 바꿔 본다(저장 안 함).
- 한 일
  - `world/batch.js` (맵 · 놀이 · 차량을 다 놓은 뒤 한 번): 같은 소품을 같은 옵션으로 4개 이상 `W.place`한 것은 96m 칸마다 인스턴스로. 2~3개와 혼자 놓인 소품, 맵 도형(`box` · `flat` · `mesh`)은 같은 재질끼리 96m 칸마다 한 메쉬(값 · 텍스처가 같으면 따로 만든 재질도 같은 재질로 본다). 침목 인스턴스 2,000여 개와 바닥 얼룩 한 장(`userData.split`)은 칸으로 잘라 화면 밖 · 먼 칸을 뺀다.
  - 거리별 단순 모델(LOD, 정의의 `lod: {near, opts}`): 벤치 36 밖(삼각형 9,470 → 2,870), 차 5종 45 밖(세단 8,712 → 4,720), 단지 나무 70 밖(가지 세 단).
  - 사람 · 노점 사람: 몸통 · 팔 · 다리마다 정점 색 한 메쉬(`character.js` bakeRig) → 한 사람 그리기 15 → 5회(그림자도 같은 만큼). 같이 노는 사람이 늘수록 차이가 커진다.
  - 화질 단계 `core/quality.js`: 높음(배율 2, 그림자 4096 부드럽게) · 보통(1.5, 2048) · 낮음(1.25, 1024). 자동이면 데스크톱 높음, 레티나(배율 1.5 초과) 보통, 터치 · 작은 화면 낮음. `localStorage 'wt.quality'`. 4단계 환경설정 화면이 이 값을 바꾼다.
  - 셰이더 미리 짓기(거리 숨김 · LOD로 가려진 칸까지), 작은 바리케이드 160 밖 숨김.

- 화면 비교: 9개 시점 픽셀 차이 0.1~0.5% (그림자 가장자리 · 구름). 벤치 앉기 · 놀이터 움직이는 소품 확인.
- 다음: 맥북에서 P → '5곳 측정' → '결과 복사'. 안드로이드는 주소 끝에 `#perf`를 붙여 성능 창을 연다(자동 화질 '낮음', 기준은 4단계의 30fps). GPU ms가 높으면 '배율' 단추로 1.25 · 1을 눌러 빨라지는지 본다(빨라지면 픽셀 문제 → 자동 배율 조절). 아파트 시점은 동 그림자(삼각형 26만)와 주차장 차가 남은 큰 몫.
- 맥북 M1 1차 측정 (2026-11-24, 화질 보통, 배율 1, 1435×743): 5곳 모두 60fps(화면 상한), CPU 4.0~6.5ms, GPU 6.1~7.6ms → 목표 안. 기본 배율 1.5 · 전체 화면에서 한 번 더 재서 '보통' 기본값을 확정한다.
- 맥북 M1 2차 측정 (기본 배율 1.5, 2152×1114): 5곳 모두 60fps, CPU 3.5~6.9ms, GPU 7.4~9.1ms → 목표 안. 픽셀 2.25배에 GPU는 평균 약 1.4ms만 늘어 맥북 GPU 시간은 주로 삼각형 · 그림자다. '보통' 기본값 확정, **1단계 그래픽 최적화 완료** (안드로이드 실측은 4단계 '낮음' 값을 맞출 때).
- 주의: `W.place`가 돌려준 소품을 나중에 움직이거나 자식을 붙이면 그 정의에 `dynamic: true`를 단다(안 달면 batch.js가 묶어 버린다: 시소 · 흔들 오리 · 뺑뺑이). 맵 도형도 움직일 것은 `userData.dynamic = true`.

## 3단계 메뉴 · 화면 정리 1차 (2026-11-24)

- 왼쪽 위는 '메뉴' 단추 + 내 이름만. 메뉴(`ui/menu.js`, Esc · 단추)는 탭 셋: 서버(연결 상태 · 주소 · 인원, 접속자와 점수표 — 예전 점수표 창을 합침) · 설정(소리, 화질, 미니맵) · 조작법(예전 왼쪽 아래 안내 글). 화면을 누르면 닫힌다.
- Esc 순서: 메뉴 닫기 → 결과 창 닫기 → 놀이 그만하기 → 메뉴 열기. 메뉴가 열려 있으면 E · R 상호작용은 막는다(`hud.modalOpen`).
- 설정은 localStorage: `wt.sound`(on · off), `wt.quality`(auto · high · medium · low, 바로 적용: 배율 · 그림자 지도 · 부드러운 그림자 · LOD 거리), `wt.minimap`(full · near).
- 미니맵(2차, `ui/minimap.js`): '내 주변'으로 정함. 오른쪽 위 180px 네모(폰 110px), 반경 45 확대, 북쪽 위. 바닥 색은 물 · 풀 · 벽돌 바닥 · 도로/건물 · 보도 · 바탕 몇 톤으로 줄이고(`tone`), 글자는 큰 장소 10곳(`PLACES`)만, 놀이 장소는 청록 마름모, 나는 호박색 화살촉. 누르거나 M 키면 가운데 '동네 지도' 창(Esc · 닫기 · 화면 누르기로 닫힘). 미니맵 캔버스에 CSS 배경색을 주면 3D 화면에 뒤집힌 자리로 구멍이 났다(브라우저 합성 문제) → 배경 없음.
- 지도 그림 3차 (2026-11-25): 월드 도형을 칠하지 않고 `minimap.js` drawMap이 layout.js 값으로 안내도를 그린다. 구역 · 도로 · 건물은 옅게, 역은 선로 띠 + 승강장만, 육교는 파란색. 체험 공간은 호박색 면: 놀이터 · 평상 · 눈사람 만들기 · 딱지치기 · 공기놀이 · 문구점(오락기 · 뽑기 · 가위바위보) · 노점(군고구마 · 호떡) · 얼음 썰매장(별사탕 줍기) · 연날리기 둘. 아래 상가는 상호(솔밭 숯불갈비 · 동화 목욕탕 · 동화 마트), 강 이름은 '은빛천'(지어낸 이름, 가운데). 글자는 나눔고딕, 흰 테두리 없음. 작은 지도용 · 큰 지도용 그림을 따로 구워 둔다(글꼴이 늦게 오면 다시 굽기).
- 지도 그림 4차 (2026-11-25): 사용자 레퍼런스(만화풍 게임 지도: 굵은 외곽선 · 동글동글한 나무 · 굽은 흙길 · 아이콘 건물)를 겨울 동네로 옮김. 눈밭 바탕 + 눈 결, 베이지 흙길(테두리 두 번 칠), 눈 덮인 둥근 나무를 빈 땅에 흩뿌림(길 · 건물 · 놀이 · 글자 자리는 `keep`으로 피함), 물결 둑 강, 침목 선로, 만화풍 건물(지붕 띠 + 외곽선). 체험 공간은 호박색 동그란 배지에 그림(그네 · 평상 · 눈사람 · 딱지 · 공기 · 오락기 · 군고구마 · 썰매 · 연) + 이름.

## 작업 방식

- 새 세션은 이 프로젝트('Winter Town') 안에서 연다. 시작할 때 GitHub용 zip(또는 저장소 링크)을 첨부하고, 이 문서와 수정 기록을 기준으로 이어 간다.
- 소품은 `winter-town-asset-pipeline` 스킬 절차대로 (Three.js 코드로 만들고 외부 모델은 크기 · 비율 참고만, 간판 · 상호는 지어낸 이름).
- 맵 요청은 2차 구획도의 구획 코드(예: SW, WP, RG)와 '요청서 복사'로 보낸다.
- 한 번 수정할 때마다: 검수(불러오기 오류 · 겹침 · 걷기 · 삼각형) → 게임 · 갤러리 · 구획도 다시 올리기 → 수정 기록 한 절 → zip → GitHub 커밋.
